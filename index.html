Layering
Layering is a core concept in TPT. Its applications include (but are not limited to):

Azure Bombs
Erasers
Some kinds of subframe tech (such as 0d tech), including applications to TPT computers
Compact storage (E-HOLE or photon stacking)

Vocabulary:

Stack: A 1x1 space where particles are layered.
Layer: Each individual layer of particle(s) in a stack.
Material: A collection of stacks.
Alloy: A material with a defensive purpose.

You either use LHR (Layering Helper Reforged) or Subframe Chipmaker to layer.
For LHR, you drag CTRL-J over an area. For Subframe Chipmaker, you drag Shift+S over an area.*

The bottom of a layer always has the lowest particle number in the stack.
The top of a layer will always have the highest (Unless the stack has been changed since saving).

*These tools are not needed, for if you get multiple elements and set the coords to the same position, it also works.

Serialization

Serialization/Deserialization is to use sensors in the “Sensors” category to manipulate properties of elements by extracting information from FILT c-type.
There does not exist a save that can present an adequate tutorial.
It is suggested you refer to the sensor pages in the official wiki and experiment yourself for a deeper grasp.
^ Above is extracted from the old docs, An attempt at an explanation of this follows.
This is gonna be a long one.

LSNS, TSNS, and VSNS all provide serialization & deserialization capabilities
LSNS handles Life
TSNS handles Temp
VSNS handles Velocity (vx/vy)

For this explanation we'll use Life as the chosen value since thats the most common, but it works identically for the other options.
SNS with a tmp of 1 will serialize
SNS with a tmp of 3 will deserialize
To serialize is to take the LIFE value of a nearby pixel, and set a nearby FILT pixel's CTYPE to the LIFE value retrieved + 0x10000000 (16^7)
To deserialize is to take the CTYPE of a nearby FILT pixel, subtract 0x10000000 (16^7), and set a nearby particle's LIFE to the new value.

The 0x10000000 (16^7) is a constant used by serialization and deserialization,
this is most commonly used in electronics to ensure a line of BRAY doesn't get cut unintentionally due to having a value of 0.
You do not need to understand how FILT works to use serialization/deserialization, Although it will help.

When taking the LIFE of a "nearby pixel", the SNS particle searches within a square radius of it's tmp2, centered at itself.
It searches top to bottom, left to right, So top left, middle left, bottom left, top middle, middle, bottom middle, ect.
The last particle it finds will be what the LIFE is taken from.
The same behavior is applied during deserialization when looking for a FILT particle to take the CTYPE of.

When applying a LIFE/CTYPE value of a "nearby pixel", the SNS particle searches much like previously, with a radius of 1.
Strictly the particles immediately around it will be affected, and every single valid one will be.
What this means is:
Every nearby FILT particle will be serialized to, replacing it's CTYPE.
OR
Every nearby particle will be deserialized to, replacing it's LIFE value.

Now for some examples:
If LSNS is placed next to SPRK, with FILT within it's tmp2's related radius, and it's tmp value set to 3,
the LSNS will take the value from the FILT, and apply it to the SPRK's LIFE.
If the FILT is set to 0x10000003 (16^7 + 3), then we subtract 16^7, leaving us with 3,
then we set the SPRK's LIFE to 3, which is the value at which SPRK activates CRAY/DRAY/ARAY/ect.
This allows the SPRK pixel to activate nearby particles every single frame given the LSNS activates before the particle to-be-activated.

This one is a more niche example but explains VSNS well,
PHOT is spawned next to VSNS next to FILT,
VSNS has a tmp of 1, so it serializes.
the VSNS sees the PHOT's velocity, PHOT starts with a velocity of 3 either diagonally or straight;
VSNS takes the PHOT's velocity of 3, adds 0x10000000 (16^7), and set's the FILT's CTYPE to that value.
The FILT now has a CTYPE identical to what we used in the last example.
What this means is hypothetically someone could, within a single frame,
Create FILT, Spawn PHOT, Set the FILT to 0x10000003, Cleanup the PHOT, Create SPRK(PSCN), Set the SPRK's LIFE to 3, Cleanup the FILT, use ARAY/CRAY/DRAY, and clean it all up like nothing ever happened.

As a harder challenge, compress it to no more than 4 pixels excluding diamond for padding and such.

Particle Order

Particle order is as the name implies, the order in which each particle in the save is read every frame

When the player places a particle of anything (excluding walls), each new particle receives the next particle ID in the order it was placed.

However, every time you save it, such as online saving or stamping, the particle order changes to a very predictable order.

Once saved, the game scans particles like reading a book: starting from the top row, moving left to right, then continuing onto the next row until every particle has been processed, (in the case of stacked particles it reads from the bottom of the stack to the top), every single frame 60 times a second.

By manipulating this predictable particle order we can make something known within the community as subframe tech.
Main
Subframe

Subframe is when you place certain elements in a way that lets them get scanned in the predictable particle order that makes them work every single frame.
You are using the fact that particle order will always be the same when saving to activate each particle at the needed time in-between each frame,
hence the name, Subframe.

Life deserialization is also useful in subframe tech, because it allows you to not rely on the specific way it all is structured. (Among other reasons)

Bomb Theory

The theory for producing bombs. It’s called “Bomb Theory” but mainly it’s for azure and azure-adjacent studies.

What is an “azure”?
“The Azure Lotus Mechanism: The ability for long-life GBMB to direct superheated WARP along objects, annihilating them; I have demonstrated this using an extrordinarily[sic] powerful bomb named the Azure Lotus... likely the most powerful bomb in TPT.”
- Ourous, the progenitor of the Azure bomb

What does that even mean?
GBMB will create positive gravity when it touches other elements (other than DMND and GBMB), at which point its life will go from 0 to some number.
The life then goes down by 1 every frame. When that number hits under 20, it will instead produce negative gravity, pushing everything away from it.
Because of this, GBMB is also “sticky” in a sense; it’s hard to explain but it basically will move toward the stuff it gets attracted to, and then subsequently get displaced by it…It would be easier to see it in action.

Superheated WARP was originally defined as WARP with tmp2 over 2000, which would cause it to become the temperature 10000K (9726.85C). This is also the only way to get an element to the temperature 10000K.
These days, it’s just the literal definition of what you’d think Superheated WARP is: Literally just hot WARP, at 9999K (9725.85C) or above; it doesn’t matter what way you achieve that temperature.

When you combine these two, it will have the GBMB constantly move around in what the WARP has melted, which will in return direct the WARP to what has not been melted,
which will make more molten material, creating a positive feedback loop that ends when there isn’t enough WARP to sufficiently heat everything, or when the GBMB has died (when life hits 1, GBMB disappears).
A way you can tell the Azure Lotus mechanism is happening is to look at the LAVA: it should be forming “clumps” of it, almost, and the black things between them is WARP.

Applications of Life Deserialization in bombs
DEUT
The primary use of life deserialization is to constantly produce high-life DEUT.
This was a revelation; prior to this, you only had so much DEUT pre-stocked to your bomb, and it was gone once you used it up.
Now, you can make as much PROT as you want, provided the DEUT does not get blocked up by elements like PLUT or CO2.

Here is an example.

You can see that the DEUT produced doesn’t actually have the exact value of 429497.
This is because DEUT shares its life values with its neighbors.

DEUT with life above 429497, when mixed with PROT, will make blasts where some of the PROT is at temp 0K (-273.15C).
The amount of 0K PROT increases with life, so 429497 is going to be your optimal* life value for making hot PROT.
*I suppose it’s moreso the highest value at which there’s absolutely zero chance you could accidentally make cold PROT.
